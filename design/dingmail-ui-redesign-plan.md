# DingMailSender UI/UX 重构方案

## 1. 目标

把现有“四步卡片式说明界面”重构为“草稿复核优先”的企业桌面工作台。

本次重构保留现有业务能力：

- SMTP 连接测试与连接信息保存
- 任务包创建、导入、重新加载
- `tasks.xlsx` 读取、修复、保存
- 任务新增、编辑、复制、删除
- 邮件预览
- 保存到 IMAP 草稿箱
- 立即发送
- 定时队列与托盘常驻
- 运行输出目录与失败重试

本次重构推翻现有界面结构：

- 不再把主界面组织成 4 个纵向说明卡片
- 不再把所有操作按钮放在同一排
- 不再让“立即发送”和“保存草稿”拥有相同视觉权重
- 不再把状态信息压成底部多行文本

## 2. 设计上下文

详见项目根目录 `.impeccable.md`。核心约束：

- 主路径是“保存草稿箱 -> 人工复核 -> 邮箱端微调后发送”
- 界面需要安静、高级、专业，适合企业内部重复操作
- 状态必须清楚，风险操作必须降权和隔离
- 任务表要支持快速扫描、筛选和定位错误

HTML 原型参考：

- `design/dingmail-workbench-no-sidebar-demo.html`

## 3. 信息架构

### 3.1 主窗口结构

主窗口采用三层工作台结构：

1. 顶部全局状态与命令栏
   - 当前任务包
   - SMTP / IMAP 连接状态
   - 创建/导入/重新加载任务包
   - 打开任务目录、打开 `tasks.xlsx`、预览操作说明

2. 指标与主工作区
   - 任务概览指标
   - 任务表
   - 右侧草稿复核面板

3. 底部运行状态
   - 失败重试
   - 运行历史

### 3.2 主路径

主路径调整为：

1. 导入或创建任务包
2. 校验任务表
3. 选中任务
4. 在右侧面板查看收件人、正文、附件、定时、校验状态
5. 点击“保存草稿”
6. 打开邮箱草稿箱人工微调

“立即发送”保留，但作为高风险次要操作出现。

## 4. 视觉系统

### 4.1 风格

方向：安静高级的企业工作台。

设计要点：

- 冷调浅色中性底，避免米色/奶油色单一主题
- 语义色只用于状态和关键操作
- 控件圆角控制在 6-8px
- 低阴影、清晰边界、高可读表格
- 少说明文字，用状态、标签、分组表达

### 4.2 语义色

- 主操作：稳重蓝
- 可保存/成功：绿色
- 定时/等待：琥珀色
- 草稿：青蓝色
- 错误/风险：红色
- 普通信息：冷调灰蓝

### 4.3 按钮层级

- `保存草稿`：主按钮
- `预览`、`加入队列`：普通按钮
- `立即发送`：风险按钮，视觉上与主按钮隔离
- `删除`：风险操作，保留确认
- `打开任务表`、`重新加载`：顶部工具按钮

## 5. 模块拆分

### 5.1 保留模块

- `src/dingmail/gui/task_runtime.py`
- 发送、草稿、渲染、任务包等业务模块

### 5.2 新增模块

- `src/dingmail/gui/theme.py`
  - 全局 QSS
  - 状态颜色
  - 按钮 objectName 约定

- `src/dingmail/gui/widgets.py`
  - `StatusTag`
  - `MetricTile`
  - `SectionPanel`
  - 任务详情/校验辅助控件

### 5.3 重构模块

- `src/dingmail/gui/main.py`
  - 只保留窗口初始化、连接配置读写、通用错误弹窗和 `run()`

- `src/dingmail/gui/main_ui.py`
  - 顶部命令栏、指标、任务区、草稿复核区、底部运行栏搭建

- `src/dingmail/gui/main_view.py`
  - 筛选、搜索、详情预览、托盘、窗口回调、SMTP 状态

- `src/dingmail/gui/main_tasks.py`
  - 任务包导入/重载、任务增删改复制、表格刷新、状态摘要

- `src/dingmail/gui/main_delivery.py`
  - 保存草稿、立即发送、定时队列、失败重试

## 6. 行为改造

### 6.1 任务表

默认列减少为：

- 状态
- 收件人
- 主题
- 正文
- 附件
- 定时
- 发送时间
- 说明

隐藏或转移到详情面板：

- 抄送
- 开头/补充内容
- 完整 Markdown 路径
- 完整附件路径
- 任务 ID
- 备注

### 6.2 筛选

新增状态筛选：

- 全部
- 可保存草稿
- 需修正
- 已保存草稿
- 定时队列
- 发送失败

筛选只影响表格显示，不改变任务数据。

### 6.3 右侧草稿复核面板

展示当前选中任务：

- 主题
- 收件人/抄送
- Markdown 路径
- 附件摘要
- 定时状态
- 校验结果
- 最近发送/草稿结果

没有选中任务时展示当前批次摘要。

### 6.4 底部运行状态

把旧底部多行状态文本改为结构化摘要：

- 任务包
- SMTP 状态
- 启用任务数
- 可保存草稿数
- 失败数
- 定时队列数
- 最近输出目录

## 7. 风险控制

- 保存草稿仍需确认，但文案强调“不会直接发送”
- 立即发送仍需确认，并明确“忽略定时设置”
- 删除任务仍需确认，并提示会写回 `tasks.xlsx`
- 已有托盘退出确认逻辑不变
- 所有发送、草稿、定时动作继续走现有校验逻辑

## 8. 验收标准

### 8.1 功能验收

- 无任务包时只能创建/导入任务包
- 导入任务包后任务表能正常显示
- 选择一条任务后右侧面板刷新
- 未连接 SMTP 时不能保存草稿、立即发送、加入队列
- 连接成功后保存草稿按钮可用
- 立即发送按钮存在但不作为主视觉焦点
- 定时队列、失败重试、运行历史仍可用

### 8.2 视觉验收

- 界面不再呈现 4 个步骤卡片
- 任务区不再出现 10 个同权重按钮横排
- 主按钮明确是“保存草稿”
- 状态不只依赖背景色，也有文本标签
- 表格可读性优于旧版

### 8.3 自动化验收

运行：

```powershell
python -m unittest tests.test_gui_main
python -m unittest discover -s tests
python -m compileall src dingmail_gui.py tests
```

## 9. 执行顺序

1. 新增 `theme.py`、`widgets.py`、`dialogs.py`、`workers.py`
2. 重构 `MainWindow._build_ui`
3. 重构 `_refresh_task_table` 以适配新列
4. 增加 `_refresh_detail_panel`、`_refresh_metrics`、筛选方法
5. 调整 `_refresh_ui_state` 的按钮状态和状态摘要
6. 拆分 `main.py` 到 `main_ui.py`、`main_view.py`、`main_tasks.py`、`main_delivery.py`
7. 更新 GUI 测试中对按钮、列数、运行历史的断言
8. 跑测试、编译和质量校验
