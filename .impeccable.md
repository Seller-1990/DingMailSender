## Design Context

### Users
This project is used by internal operators who batch-send enterprise emails from local task packages. The most important workflow is saving selected emails into the mailbox Drafts folder first, then manually reviewing and adjusting them before final sending.

### Brand Personality
Quiet, reliable, polished, professional. The interface should make high-volume email work feel controlled and auditable, not playful, decorative, or marketing-like.

### Aesthetic Direction
Use a high-end desktop workbench style: light neutral surfaces, clear table density, restrained borders, semantic status colors, and precise spacing. Avoid beige-only palettes, decorative gradients, oversized cards, noisy shadows, and tutorial-like text blocks in the main interface.

### Design Principles
- Draft-first: saving to drafts and human review are the primary path.
- Risk separation: destructive or irreversible actions must not look equal to routine actions.
- Status visibility: SMTP, package, validation, queue, and run output states should be visible without opening dialogs.
- Scan first: task lists should support filtering, fast comparison, and row-level issue recognition.
- Recover inline: validation errors, missing paths, and failed sends should be actionable in context.
